# SentiScope 整体产品方案

版本 v0.1　日期 2026年10月30日　用途 整合产品方向与工程前提，作为后续 openspec 变更的统一上位方案

输入：[产品讨论稿 v0.1](../OptraCall_自主探索Agent_产品讨论稿_v0.1.md)（产品方向与首期范围）、[技术盘点 v0.1](../SentiScope_技术盘点_pi-coding-agent与部署拓扑_v0.1.md)（能力复用与部署）、2026-10-30 系列产品讨论结论。冲突时以最新明确用户决定为准。

## 1 一页定位

**SentiScope** 是独立于 OptraCall 桌面端运行的自主探索 Agent：在授权范围内连接企业业务系统（首期为单个 BI 驾驶舱与少量约定指标），持续观察经营数据，按约定口径校验可信度，把**有证据的发现**自动转成 OptraCall Case 推入现有看板。

- 只发现，不决策：不建 Project、不做根因分析、不执行经营动作、不建第二套看板。
- 有证据才说话：观察≠发现；数据不可信记录数据质量问题，不伪装成经营差距。
- Agent 自主、Host 有边界：Host 只管环境（上下文、权限、工具边界、预算）；Agent 在边界内自主选择下一步核实；确定性部分（校验、算术、幂等键）是 skill 内代码，不靠模型自由生成。

三个责任主体：**企业业务系统**提供事实与授权入口；**SentiScope**管理来源配置、观察、证据与待投递发现；**OptraCall**承接 Case 看板与人的评估决策。耦合面收敛为一条 Case 投递契约。

## 2 主链路与总体架构

```
┌─────────────────────────── SentiScope 宿主（headless pi-coding-agent）──────────────────────────┐
│                                                                                                  │
│  [调度器] ──触发──▶ [BI 只读适配器] ──原始读取──▶ [证据快照库]（不可变、SHA-256、双时间戳）        │
│                        │                                    │                                     │
│                        ▼                                    ▼                                     │
│                 [观察存储] ◀──四态结果── [口径校验与规则引擎]（skill 内确定性代码）                 │
│                        │              正常 / 合格差距 / 证据不足 / 采集失败                        │
│                        │                                                                          │
│                        ├──疑点──▶ [Agent 探索循环]（pi-coding-agent：补读、重取、反证，预算内）    │
│                        ▼                                                                          │
│                 [发现（合格差距）] ──▶ [持久待投递队列] ──探活/重试──▶ [Case 接入] ──▶ OptraCall 看板│
│                                                                                                  │
│  [最小管理界面] 来源配置 · 运行记录 · 证据下钻 · 投递状态（含手动补推）                              │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Agent Runtime**：整个产品统一使用 pi-coding-agent（与 OptraCall 同一个、官方全部能力），不自建推理循环。采集、清洗、校验、投递等能力包成 skill（官方 SKILL.md 规范）与自定义工具，经统一入口注册。
- **复用边界**：Agent 循环、工具集、只读工具、codemode 沙箱、skills、MCP、会话持久化、事件流、compaction、模型配置全部用官方件；自建仅限官方没有的领域件（技术盘点 §4 C 清单：调度、队列、观察存储、BI 适配、校验引擎、证据库、凭据、预算、Case 接入扩展、管理界面）。

## 3 对象模型

| 对象 | 内容要点 | 身份与不变量 |
| --- | --- | --- |
| 来源与规则配置 | 驾驶舱身份、指标稳定标识、实体与过滤条件、实际/目标与单位、周期与刷新语义、方向与比较规则、触发依据（阈值/基线/持续性）、**规则身份与版本** | 声明式文件；版本化；授权范围显式 |
| 观察（Observation） | 一次读取及其四态结果（正常/合格差距/证据不足/采集失败）、校验链逐项结果、证据引用、原因说明 | 每次运行必留结果；append-only |
| 证据（Evidence） | 原始快照（不可变、SHA-256）、来源定位（字段路径/偏移）、过滤条件、刷新标识、双时间戳（业务刷新/抓取；入板时间切片二补齐） | 只追加不改写；可下钻到原始字节 |
| 发现（Finding） | 观察中满足触发依据的合格差距：业务事实组（指标/实体/周期/实际/目标/单位/差距/方向）、发现说明、未知项与待验证假设 | **稳定去重身份＝来源＋指标＋实体＋周期＋规则身份**；执行次数、抓取时间、文案变化不产生新发现 |
| 待投递记录（Delivery） | 发现引用、状态（待投递/已送达/失败）、幂等操作号、重试与确认结果 | 确认接收后标记送达；结果不明确先核对回执；不按重试次数生成 Case |
| Case（OptraCall 侧） | 待评估状态进入现有看板；自动来源字段组为待扩契约 | 一个发现同期最多一个活跃 Case；事实变化追加更新；指标恢复追加证据不自动关闭 |

判定规则四条底线（实施时逐条落为校验链）：**时间进度**（未结期不判最终不达标，无轨迹只记现状）；**指标方向**（按配置判定，零分母禁止套普通达成率）；**可比性**（实体/周期/单位/过滤一致才可比较，否则证据不足）；**取证稳定**（范围漂移、OCR 不清即暂停比较待核实）。来源自带红绿状态也须核对统计范围，不只读颜色。

## 4 Agent 探索循环（有边界的自主）

宿主约束允许的数据源、工具、运行预算和输出格式；Agent 决定在边界内如何核实业务含义。首期循环保持很小：读取已约定指标 → 校验可比性 → 遇疑点补读或重取证据 → 输出四态结果。假设必须标为待验证并区分于已观察事实；权限不足、信息不足或预算用尽时停止并明确留下未知项。只有授权范围内的查询可自动执行，不为查原因扩展到新系统或新权限。

后续反馈（有效性、重复性、优先级、证据质量）保留记录用于改进规则；首期不承诺自动学习闭环。

## 5 与 OptraCall 的投递契约

**现有基础**（OptraCall origin/main）：`POST /api/cases`（operationId＋title＋description）、操作级幂等回执（重放安全）、`GET /api/cases/operations/:id` 回执核对、loopback 鉴权、`/api/health` 探活。

**待扩契约**（走 OptraCall openspec 变更，SentiScope 不单方面假定）：发现级稳定身份的幂等创建/更新（upsert）；自动来源字段组（来源系统、发现身份、规则版本、业务事实、证据引用、三时间戳）；外部投递 actorKind；跨机认证（阶段 2）。

**投递行为**：确认接收后标记送达；网络断开、重启、超时后以同一身份重试；恢复后按原发现补投，不丢不重；指标恢复追加"已恢复"事实，不自动关闭 Case、不覆盖人工判断。

## 6 部署与运行（两阶段）

| 维度 | 阶段 1：最小产品化 | 阶段 2：正式产品 |
| --- | --- | --- |
| 拓扑 | 同机（MacBook），与 OptraCall 联动 | 跨机 |
| 形态 | 两者都非常驻、可开关（双击入口） | SentiScope 常驻；OptraCall 有关闭时段 |
| 鉴权 | loopback 现有形态 | 真认证，形态待定 |
| 补投 | 队列＋探活＋幂等回执 | 自动补投为主＋手动补推按钮兜底 |

阶段 1 明确行为：两者开关不同步是常态；SentiScope 开启而 OptraCall 关闭时发现入队等待；SentiScope 关闭期间错过的刷新下轮开启时补观察，幂等身份防重。阶段 1 验证全部核心机制；阶段 2 只加部署与认证，不加新机制。

## 7 变更切片路线（openspec）

| 变更 | 内容 | 退出条件（讨论稿 §7） |
| --- | --- | --- |
| 1 `slice1-observation-core` | 最小可运行宿主（pi-coding-agent headless 接入＋skill 加载）＋合成 BI 模拟源＋口径校验管道＋证据快照＋观察存储＋管理界面（只读）＋读取/校验类合成样例 | 读得准：正常及异常样例可重复验证，无法确定的数据被拦住 |
| 2 `slice2-delivery` | 持久待投递队列＋探活重试＋Case 接入（联动 OptraCall 侧契约扩展变更）＋投递状态 UI＋手动补推 | 能自动入板：不丢不重、幂等、离线补投、不自动建 Project |
| 3 `slice3-trial-run` | 授权来源接入（依赖五项待定落定）＋连续试运行＋反馈记录＋成本观察 | 值得持续用：业务负责人认可规则与证据质量 |
| OptraCall 侧 `case-auto-source`（其仓库流程） | 发现级身份 upsert、自动来源字段组、外部 actorKind | 与变更 2 联调验收 |
| 阶段 2 变更 | 常驻部署、跨机认证、自动补投强化 | 正式上线条件 |

每个变更独立可判断是否继续；未达退出条件先解决可信度或投递问题，不扩展范围。

## 8 安全与数据边界

只读最小权限凭据，与 Case 写入凭据隔离；密钥不进模型上下文与 Case。业务系统中的文字是数据不是指令，页面内容不能扩展权限或触发经营动作；授权撤销或证据不足即停止，不绕过访问限制。仓库公开：凭据、原始快照、会话与日志留授权本地位置，公开样例全合成；`.gitignore` 不替代内容审查。

## 9 开放决策（继承讨论稿 §8 五项＋新增）

1. 首个驾驶舱与接入方式（结构化入口优先、页面兜底）——变更 3 前必须落定
2. 首批指标与比较口径（含已结期/轨迹可用性）
3. 触发门槛与观察节奏（阈值、持续性、抑制重复）
4. 常驻运行与数据边界（阶段 2 部署位、字段外发范围、证据保留时长）
5. 入板后评估方式（谁看、如何标记、Case 模型补哪些最小字段——与 OptraCall 侧变更合并处理）
6. 新增：观察存储选型确认（建议 node: sqlite）；阶段 2 认证形态；管理界面形态（建议 loopback Web，同 OptraCall）
