# SentiScope 整体产品方案

版本 v0.3　日期 2026年11月01日　用途 最小产品化方案与后续 openspec 变更的统一上位方案

输入：[产品讨论稿 v0.1](../OptraCall_自主探索Agent_产品讨论稿_v0.1.md)（产品方向历史输入）、[技术盘点 v0.1](../SentiScope_技术盘点_pi-coding-agent与部署拓扑_v0.1.md)（工程能力历史盘点）、2026-10-30 与 2026-11-01 用户产品决定。公网获取逻辑只参考本机 `/Users/huangbo/Dev/Projects/deep-research` 的检索架构，不复制其产品、代码或凭据。冲突时以本版与用户后续明确决定为准。

本版将最小产品从“BI 轮询后自动创建 Case”收缩为：**用户导入数据 → 清洗形成标准数据集 → 真实 Agent 做描述性自主探索，并在需要竞对／行业基准时通过受控公网检索补证 → 输出有证据的 Case 候选。** 自动投递、真实 BI 连接、持续轮询和通用爬虫不再是 MVP 前置。

## 1 一页定位

**SentiScope** 是运行在用户本机的自主数据分析 Agent。它接收用户主动导入的内部数据；当目标、历史、竞对或行业基准需要外部资料时，Agent 在 Host 受控工具内发起公网搜索、选择性读取公开页面并保存快照证据；在保留原始证据和清洗血缘的前提下，通过与**目标、历史、竞对、行业**的差距进行描述性分析，形成值得人进一步评估的 Case 候选。

- **描述性优先**：回答“发生了什么、与哪个基准相差多少、证据在哪里、还有什么不知道”；不做预测、不断言根因、不自动决策。
- **Case 候选不是 Case**：MVP 只形成候选并支持人工复核，不自动写入 OptraCall，不建 Project，不执行经营动作。
- **真实 Agent 是必要能力**：Agent 自主选择要检查的比较、调用工具补证或反证、放弃不成立的假设；固定规则计算不能冒充自主探索。
- **清洗不消灭原始事实**：原始文件与网页快照不可变，标准数据集是可重放的派生版本，任何修正、填补、剔除和单位换算都有记录。
- **没有合格问题也是正常结果**：Agent 不为完成数量而制造候选，证据不足时输出观察、数据质量问题或待补证项。
- **Agent 自主、Host 有边界**：Host 管数据工作区、搜索 Provider、网络边界、工具权限、模型与预算；Agent 决定探索步骤与搜索词。算术、统计、校验、转换和身份生成由确定性工具完成。

## 2 MVP 主链路与职责

```
用户导入 CSV / XLSX ─▶ [原始证据库：原字节＋SHA-256＋来源时间＋定位]
                                │
                                ▼
                   [数据画像与清洗工具]
                   类型 / 缺失 / 重复 / 单位 / 期间 / 实体
                                │
                                ▼
                   [标准数据集版本＋质量报告＋转换血缘]
                                │
                                ▼
          [真实 pi-coding-agent：描述性自主探索]
          选择基准 → 确定性计算 → 需要外部基准时发起补证 → 反证 → 放弃或形成候选
                                │
             Agent 调用 Host 受控工具，Host 只管配额、边界与取证
                                ▼
          [web_search] → 搜索命中（标题／摘要／URL，仅是线索）
                                ▼
          [fetch_page] → Agent 选择少量公开 URL；Host 做 SSRF／robots／大小／重定向校验
                                ▼
          [read_snapshot] → 快照正文分页读取；保存原文、引用与来源等级
                                │
                         ┌──────┴──────┐
                         ▼             ▼
                [观察与证据记录]   [Case 候选门禁]
                                      ▼
                      [候选看板与人工复核（SentiScope）]

后续且不属于 MVP：人工接受的候选 → OptraCall Case 投递契约 → 原 Case 看板
```

职责边界：

- **用户**提供数据、目标与内部口径，配置或批准搜索 Provider 与公网预算，确认模型和数据出口，并判断候选是否值得处理。
- **SentiScope**保存来源证据、执行可重放清洗、提供确定性分析工具与受控检索工具、运行真实 Agent、校验候选证据并呈现候选。
- **公网搜索与页面**只提供带发布时间和适用范围的公开对比事实；搜索摘要不是证据，页面文字是数据而不是对 Agent 的指令。
- **OptraCall**在后续承接被接受的 Case；MVP 不依赖 OptraCall 启动或修改其代码。

## 3 核心：问题如何发现、定义与成立

### 3.1 首期只做四类可解释差距

| 比较类型 | 描述性问题 | 确定性输出 | 成立所需口径 |
| --- | --- | --- | --- |
| 目标差距 | 某实体、某指标、某周期是否低于或高于目标？ | 实际－目标、差率或达成率、指标方向 | 目标来源明确；实际与目标的实体、周期、单位、范围和指标定义一致；未结期不能直接判最终不达标 |
| 历史差距 | 与去年同期或约定历史期相比发生了什么变化？ | 同比增减额、同比增减率、必要的环比描述 | 同期同范围；上年基数为零或负数时不套普通增长率；不把季节波动自动解释为问题 |
| 竞对差距 | 自身增速与指定竞对同期增速相差多少？ | 双方增速、增速差（百分点）、各自数据来源 | 指标、市场、周期、币种／单位和公开披露口径可比；竞对身份与报告期明确；不能用不同业务口径硬比 |
| 行业差距 | 自身增速是否低于行业或细分市场基准？ | 自身与行业增速、差值（百分点）、行业数据时点 | 行业分类、地域、市场范围、周期与指标定义一致或差异可解释；行业数据滞后必须显式展示 |

分布、趋势、结构和异常波动可以形成观察，帮助 Agent 选择下一步比较；**没有基准或业务意义的波动不直接成为 Case 候选**。根因、预测评分和自动行动建议不属于描述性候选结论。

### 3.2 Case 候选的统一定义

一个候选必须能完整回答：

> **谁**的**什么指标**，在**哪个周期和范围**，与**哪个明确基准**相比，出现了**多大的方向性差距**；为什么这个差距值得关注，依据是什么，还有什么不能解释。

候选最少包含：比较类型、指标与实体、周期与过滤范围、实际值、基准值、差距与方向、业务重要性依据、计算工具记录、原始与标准数据引用、支持证据、已检查的反证、数据质量限制、未知项、本次搜索覆盖与选择上下文、人工复核状态。**待补证项属于观察／补证列表，不是 Case 候选；只有通过全部门禁的记录才进入候选看板。**

### 3.3 候选门禁

1. **可比性**：指标定义、实体、周期、单位、币种、地域与过滤范围一致；任何关键项不明都不能硬比。
2. **计算可复现**：差值、差率、增速与百分点差均由工具计算并保存输入、公式、输出和工具版本；模型心算或文案不是证据。
3. **业务重要性**：按指标／比较类型配置的重要性阈值、最小样本或最小作用范围判断；不设“所有指标统一超过 10%”之类的伪通用标准。阈值只是筛选条件，不等于根因或决策。
4. **证据资格**：每个事实都能下钻到标准数据行、原始文件单元格／行或公网快照位置；来源、发布时间、抓取时间和转换血缘完整。
5. **支持与反证**：Agent 至少检查合理的替代切片、数据质量解释或反向证据；无法解释的冲突应降级为待补证观察，而不是选择有利数字。正向与零候选运行都记录已搜索的指标、实体、切片、基准和舍弃原因，避免只挑极端切片。
6. **诚实表述**：标题只陈述观察到的差距，不把相关性写成原因，不把行业／竞对数据写成自身经营结果。
7. **人工复核**：只有通过门禁的候选才进入 SentiScope 候选看板；保留、排除和补充说明是人工动作，不自动创建 OptraCall Case。

### 3.4 数据清洗与标准化

MVP 清洗能力是 Agent 可调用、用户可检查的工具链，不是不可见的一键黑盒：

- 画像：行列规模、字段类型、缺失、重复、异常值、日期覆盖、实体与单位分布。
- 标准化：字段映射、类型解析、日期与时区、实体别名、单位／币种、指标字典和必要的长表结构。
- 质量处理：重复、空值、非法值、表头错位与混合单位必须给出处理策略；禁止静默删除、静默填补或猜测单位。
- 版本与血缘：原始资产 → 解析结果 → 清洗步骤 → 标准数据集版本逐层引用；每次转换保存工具／参数／版本、输入输出哈希和受影响行定位。
- 用户可见：清洗前后字段、质量问题和标准数据预览可核对；无法可靠清洗的部分保留未知并阻止相关比较。

### 3.5 公网对比数据检索：deepresearch 模式，不做爬虫

公网能力采用“Agent 自主研究 + Host 受控工具”的 deepresearch 模式。**不做通用爬虫、不做站点遍历、不做链接批量抓取**；Host 也不替 Agent 写搜索词或排序结果。

#### 工具链

| 工具 | Agent 自主性 | Host 边界 |
| --- | --- | --- |
| `web_search(query)` | Agent 根据缺失基准、竞对／行业口径和未知项自主构造搜索词，可改写、放弃或追加搜索 | 只调用用户配置的搜索 Provider 链；执行搜索配额、瞬时错误 failover、出口扫描与调用留痕；返回 URL／标题／摘要，标记来源等级与已fetch状态 |
| `fetch_page(url)` | Agent 从搜索命中或用户提供的种子 URL 中自主选择少量页面读取 | 只读 GET；SSRF 前后校验（含重定向最终 URL）、robots／条款、大小／超时／内容类型、禁止登录与反爬绕过；保存原始快照后返回 bounded excerpt 与 snapshotId |
| `read_snapshot(snapshotId, offset)` | Agent 需要核对原文、表格或数字时自主分页重读 | 只读取本次运行已保存快照；返回有界文本窗口，不把整页原文无限塞入模型 |

#### 搜索 Provider 链

- Provider 是可替换 Adapter：搜索输入为 query 与确定性 `callKey`，输出为标准化 `SearchHit(url,title,snippet)`；配置在本地数据目录，密钥只经环境或本机授权存储，不进仓库、模型上下文或 Case。
- 默认支持通用 HTTP Search Adapter（endpoint／字段映射可配置），可按需增加 MCP stdio 或模型内置 web-search Adapter；瞬时错误（429、限额、5xx 等）才切换下一 Provider，其他错误如实失败。
- 未配置 Provider 或配额耗尽时工具返回错误与“收束提示”，Agent 不得把搜索失败伪装成无证据结论；运行可正常以 limited／待补证结束。

#### 证据规则

- **搜索摘要只是线索，不是证据**。候选中的外部数字必须来自已保存 `SourceSnapshot` 的原文、表格单元格或可定位引用。
- 快照保存 URL／最终 URL、标题、正文文本、原始字节或规范化正文哈希、发布时间（可得时）、抓取时间、内容类型、解析状态、来源等级与 `callKey`。
- 原文引用必须逐字、连续、有位置；数字引用带实体、期间、单位、币种／范围校准。来源等级（一手公告／统计机构／二手转述等）在快照创建时记录。
- 重要外部数值要求至少两个独立来源或明确说明单源限制；二手来源不能冒充一手。搜索结果排名、点击顺序和模型自述不构成证据资格。
- 页面内容是不可信数据：不执行脚本，不把页面指令当作权限，不向模型返回未裁剪的原始 HTML；下游只接收 bounded excerpt／evidence pack。

#### 配额与运行口径

- 搜索、页面读取、快照读取和墙钟分别设预算；配额不足以错误值返回并提示 Agent 收束，不以隐藏重试或绕过 Provider 提高产出。
- 每次搜索词、命中列表、选择／放弃 URL、fetch 结果、read 窗口和 verdict 进入 append-only 研究事件，形成可审计调查轨迹。
- Host 不预选指标、候选或 URL。用户可提供少量种子 URL／偏好域名，但必须显式标记为用户输入，不能与 Agent 自主选择混淆。

## 4 对象模型

| 对象 | 内容要点 | 身份与不变量 |
| --- | --- | --- |
| 搜索事件 SearchEvent | Agent 发起的 query、Provider、命中列表、配额、选择／放弃原因与 `callKey` | append-only；搜索摘要不是证据；Host 不代替 Agent 写 query |
| 来源资产 SourceAsset | 用户上传文件、搜索命中后选择的页面快照、原始字节／规范化正文、URL／最终 URL、发布与抓取时间、来源等级 | 原始内容不可变；内容 SHA-256；来源文字不具指令权限 |
| 快照读取 SnapshotRead | snapshotId、读取窗口、offset、返回摘要与事件引用 | 只读已保存快照；窗口有界；不向模型倾倒整页原文 |
| 标准数据集 DatasetVersion | 数据字典、标准记录、单位与期间语义、质量报告、转换步骤、上游资产引用 | 版本化、可重放；输入输出哈希与行级血缘完整；不改写旧版本 |
| 基准定义 BenchmarkDefinition | 目标／历史／竞对／行业类型、基准身份、指标、范围、周期、方向、重要性阈值与来源 | 基准不得由模型编造；版本与适用范围显式 |
| 探索运行 ExplorationRun | 真实模型与会话身份、数据版本、工具权限、搜索 Provider 与网络边界、预算、事件、停止原因 | 一次运行可恢复、可审计；模型／工具／配置身份可追踪 |
| 观察 Observation | 一次确定性画像、查询、比较或补证的结构化事实、计算与证据引用 | append-only；观察不必然是问题；模型 prose 不能独立成为观察 |
| 证据 Evidence | 原始或派生内容引用、行列／单元格／网页定位、查询与转换血缘、支持／反证角色 | 可下钻、可复核；事实与证据引用一一对应 |
| Case 候选 CaseCandidate | 四类差距之一、业务事实、重要性、支持与反证、限制、未知项、复核状态 | 证据门禁通过才可提交；候选不是 Case；人工状态与自动事实分离 |
| 投递记录 Delivery | 后续候选接受后进入 OptraCall 的可靠投递 | **移出 MVP**，不预建队列与契约实现 |

## 5 Agent、工具与真实运行边界

整个产品继续使用 pi-coding-agent 官方 Runtime、会话、事件、skills、自定义工具与 codemode，不自建推理循环。Host 不规定“必须先同比再竞对”的固定分析状态机，只提供数据版本、可用基准、工具、权限和预算。

MVP 领域工具至少包括：文件导入与解析、数据画像、可重放清洗、标准数据查询、目标／历史／竞对／行业比较、`web_search`／`fetch_page`／`read_snapshot` 公网研究工具、观察记录、候选提交。Agent 自主选择比较、搜索词、读取页面与补证路径，可返回零候选或因外部证据不足结束为待补证。

真实模型调用是切片二的验收组成，不再用会话探针代替。实施前须固定模型配置、数据出口、搜索 Provider、网络边界与预算；用户导入的数据只在本次明确授权范围内进入模型。Host 对实际模型请求和工具结果执行字段级出口控制，验收必须证明未批准字段不会经 provider 请求、搜索词、网页 URL／头部／正文或日志外传。CI 使用合成数据和受控模型／工具替身，真实模型质量验收单独记录，二者不能互相冒充。

## 6 最小管理界面：参照 OptraCall

UI 以 OptraCall 实际应用而非旧 SentiScope Demo 为参照：248px 可折叠侧栏、64px 顶栏、系统字体、紫色 accent、细边框、紧凑卡片、浅色／深色主题和宽右侧详情抽屉。保留 SentiScope 的对象与文案，不复制 OptraCall 的项目／聊天工作流。

- **Case 候选看板（默认）**：搜索、复核状态筛选、卡片／列表切换；卡片显示比较类型、差距、当前解释、未知项／下一步、证据数和更新时间。
- **探索工作区**：数据版本与模型上下文条、Agent 活动与工具事件、观察记录、停止原因；用户能看到 Agent 正在比较什么，但 Host 不预先指挥步骤。
- **数据集**：导入、画像、清洗前后预览、标准字段与质量问题；宽屏使用 286px 右侧导入面板，窄屏转为独立视图。
- **来源**：内部文件与公网页面统一展示原始证据、发布时间／抓取时间、解析状态和授权范围。
- **候选详情**：宽右抽屉，包含概览、比较计算、支持与反证、证据与血缘、历史；人工保留／排除不改变原始观察。
- 原生对话框、键盘焦点、Escape、状态非纯颜色表达、减少动效和响应式行为与 OptraCall 对齐。

## 9 安全、数据与质量边界

- 用户导入文件、内部目标与经营数据不进入公开仓库；公开测试只使用合成文件和合成网页快照。
- 真实模型、公网访问和用户数据外发分别记录授权与范围；本机计算不等于无数据出口。
- 公网只读搜索与选择性读取，不做爬虫或站点遍历；不绕登录或反爬；搜索摘要不是证据，网页内容不得扩大权限。上传文件只落在隔离工作区，不信任宏、脚本、公式或 HTML。
- 原始资产不可变，标准数据可重放，候选只引用持久观察和证据；数据质量问题不能包装成经营问题。
- 描述性差距不等于根因、预测或行动方案；人工候选复核不等于自动学习。
- 切片二通过要求真实模型路径、确定性工具、证据门禁和 UI 分别验证；模拟模型 PASS 不能替代真实 Agent 产品验收。

## 10 待确认的最小决策

1. **导入格式**：建议 MVP 先支持 CSV 与 XLSX；PDF、图片 OCR、数据库与真实 BI 后置。
2. **公网搜索 Provider**：采用本地配置的 Provider 链（先做通用 HTTP Adapter，必要时增加 MCP／模型内置搜索）；密钥只进本机环境。需用户确认首个真实 Provider、配额与偏好域名；未配置前只做合成检索验收。
3. **标准数据模型**：以“指标＋实体＋期间＋数值＋单位＋维度”为核心，保留原始字段和扩展维度，不预设所有行业统一大宽表。
4. **重要性阈值**：随首批指标与比较类型配置，不能由 Agent 自行编造或全局一刀切。
5. **真实模型与数据出口**：实施真实运行前固定模型、预算、可发送字段和网络范围；未确认前只用合成受控运行做工程检查。
6. **UI Gate**：以切片二 `clickable/` 的 OptraCall 风格 Demo 为准，用户确认后才改造正式界面。
