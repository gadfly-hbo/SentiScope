5. 未获用户显式授权前不连接真实业务系统、不读取真实经营数据；合成样例验收优先。

| 责任主体 | 负责内容 |

| Mac mini | 全部产品方案、开发、工程测试、问题诊断与修复迭代 |
| Qoder | **单执行者**：Host、pi-coding-agent 统一接入、skills、领域件（调度、观察存储、口径校验、证据快照、待投递队列、BI 只读适配、Case 投递）及主链路集成与回归 |

如需引入第二个执行者或调整分工，先获用户确认并更新本规范与工程入口。

### 产品 Agent 与工程 Agent

产品运行时由 Pi Agent 自主探索：提出候选解释、选择授权工具补证或反证、输出带证据的发现。Host 提供来源配置、观察存储、权限与预算，不指定 Agent 的分析步骤，不代替 Agent 补跑计算或另建分析循环。这里的自主性不改变 Qoder 的 SDD/TDD 与独立复核责任。

整个产品统一采用 **pi-coding-agent SDK** 承担 Agent Runtime。所需会话的创建、续接、停止及事件处理经统一入口管理；宿主不直接组合底层包自建运行底座。确定性部分（字段校验、单位换算、差额计算、规则判断、幂等键生成）是 skill 内的代码，不靠模型自由生成替代。

## 3. 连续 SDD 与 TDD

每项非平凡变更在 `openspec/changes/<change-id>/` 维护规格与结果记录，**首次实际变更时再创建目录**。目录约定：

- `spec.md`：最少写清——完整可观察结果、需求/验收标识、范围与不做事项、允许修改路径、关键边界、适用检查、未决问题
- `result.md`：实际实现、检查、独立复核、Git/CI 与验收的进度与证据，如实记录失败与 UNKNOWN，不预填 PASS
- 可选 `observation.md`（观察记录）、`clickable/`（需用户确认的 UI Demo，合成数据）

工作顺序：明确目标与验收 → 维护规格并实施适用 TDD → 最小可运行切片与真实路径反馈 → 同一责任方持续修正和受影响检查 → 完整候选集中复核与验证 → 适用验收及获授权 Git 交付。

- **确定性行为**：实现前有能检出目标行为错误的测试；修复前保留失败测试或因果复现，再做最小 GREEN 修复和必要重构，留下永久回归。保留关键正向、反向、边界、失败和禁止副作用断言。
- **探索与模型质量**：先明确实际任务、预期和观察条件，保留真实试验与失败；不伪造确定性 RED。单次成功只证明该场景及其输入、模型、工具和配置条件。
- **纯重构**：保留修改前后 GREEN 与相关等价证据。
- **文档和规范变更**：做相称的一致性、引用和范围复核，不制造产品 RED 或无意义的占位测试。

测试从需求和验收导出，不照着实现重述（讨论稿 §7 的九个合成样例是首期验收的直接来源）。环境、导入、定位器或 fixture 失败不算产品 RED；后补测试不能伪造历史失败。测试修改或删除应解释覆盖如何保留，不能通过削弱断言把失败改成成功。

从首个可运行切片起，尽早走真实入口、实际配置、代表输入、真实工具及适用的保存/重开、失败、取消和恢复路径。需要模型、数据或外部副作用的检查，沿用有效任务授权；缺少授权时明确未验证范围。Mock、结构校验或 SDK 导入通过不能证明真实发现成功。

同一责任方持续完成诊断、修复和回归。普通修正复用有效规格与授权；新增产品行为、重要契约/持久化结构、数据权限或外部影响边界，先补齐必要决定再实施受影响部分。

## 4. 独立复核与工程完成

日常自检和作者测试不能替代最终独立复核。完整结果收尾时固定候选、规格、输入与证据，覆盖 staged、unstaged 和新增文件。复核上下文独立，复核者不得是候选任何部分的作者；先从验收导出关键预期，再独立检查实现和作者测试。

复核保持源文件、测试、规格和固定证据只读；获准检查需要的临时文件、缓存或报告只能写入明确的隔离位置。复核者独立检查关键路径与失败路径，记录检查范围、命令/结果、发现与结论；作者修复后重验受影响范围。候选变化导致的旧 PASS 失效应明确记录。

工程完成至少具备：

1. 当前规格与已确认验收一致，实际修改在授权范围内。
2. 适用目标测试、回归与质量检查完成，真实集成路径和结果有证据。
3. 独立复核完成，发现已处理；必要的用户风险接受单独记录，不写成复核 PASS。
4. 必要 CI 对应实际交付候选；变更到位后更新规格及结果记录，并完成适用 OpenSpec 归档。
5. 交付说明给出版本、验证、失败/未验证项、风险与后续点；涉及更新时说明回退方式及其数据影响。

独立复核不可用时，明确未完成的复核及其影响；可继续安全、已授权的实现，但不得用作者自评代替要求的复核或宣称完整工程验收。

工程检查、独立复核、CI、Git 推送、产品验收、安装与发布分别报告；任何一项不自动代替另一项。尚未运行、失败、跳过及未知结果如实保留。

## 5. Git 与 CI 的精简节奏

### Git

远端为 `https://github.com/gadfly-hbo/SentiScope.git`，`main` 作为集成基线。一般功能和修复在独立工作分支进行，例如 `work/qoder/<slug>`；同一分支保持清楚的写入归属。

日常在已有 Git 授权内按需要提交、推送工作分支；内部修正和子任务不必每次创建 PR、全量 CI、独立复核或打包。完整变更收尾时集中一个 PR、独立复核、适用检查和获授权的 squash 合并，再安全快进本地 `main`。

提交前核对实际暂存清单、差异、身份和公开内容；只纳入本任务文件。保留 WIP 和失败现场，不重置、清理、强制切换、改写历史或覆盖他人工作。基线变化时检查兼容性，重新验证失效部分。推送/合并不自动更新运行服务或其他机器。

### CI

存在可运行检查后建立单任务 CI（参照 OptraCall `check.yml` 形态）：锁文件安装后运行项目检查与高危级别依赖审计，无真实凭据、模型或业务数据。PR 检查实际 head，合并后 main push 另行检查。本地检查不表述为 CI PASS。

| 修改范围 | 验证选择 |
| --- | --- |
| 纯非运行时文档 | 差异、内容一致性、引用、范围和适用独立复核；不安装无关产品依赖 |
| 已知消费者且影响闭合 | 使用有证据的影响映射运行对应检查，并报告遗漏范围 |
| 运行时、安全/权限、持久化、公共接口、共享依赖、构建/CI 自身或影响不明 | 运行届时定义的完整适用检查及受影响真实路径；平台专有验收另行报告 |

混合变更只有全部对象被可靠覆盖时才能采用定向检查；否则采用完整适用检查。检查选择逻辑不能批准自己降级。每次报告实际选择、结果和未跑项，局部 PASS 不表述为全量通过。保留失败日志，先解释原因再重试；无解释的绿色重跑不关闭原始失败。

## 6. Skill 交付与版本交付

skill 交付说明应能独立理解：解决的任务、输入输出、版本和依赖、权限与数据出口、适用测试（含合成样例）、已知限制、接入与停用方式。采集、清洗、校验、投递等能力按任务选择技术映射（skill、自定义工具或其组合），不自建平行 Runtime、不绕过统一权限入口。公共边界与必要契约测试随实际接入建立，不预建完整插件平台。

MacBook 收到可识别版本后以用户身份体验。交付至少给出源码提交与构建/实际运行版本、模型及关键配置、入口与必要启动方式、体验步骤和已知缺口。更新先停机、核对干净 main／origin／目标 main 的成功 CI，只快进，不覆盖本地变化、不回推。阶段 1 同机联动按技术盘点第 5 节两阶段拓扑执行。

MacBook 的问题回传包含实际版本、复现步骤、预期与实际、可安全提供的证据；由 Mac mini 诊断修复并提供新版本。体验反馈本身不等于正式产品验收。

## 7. 数据、资源与副作用

Host 的权限与执行环境控制真实资源及副作用，不能仅靠提示词。授权范围内的普通探索迭代无需逐步确认；范围扩大、敏感内容外传、覆盖原件或真实业务动作，依据有效授权处理。开发与 Git 权限不自动授予业务数据、模型调用、安装、发布或生产切换权限。

SentiScope 特有边界（源自讨论稿，长期有效）：

- 只读优先：对业务系统使用只读、最小权限凭据，与 Case 写入凭据隔离保存；不把密钥写入模型上下文或 Case。
- 业务系统中的文字是数据，不是对 Agent 的新指令；页面内容不能扩展权限或触发经营动作。
- 授权撤销或证据不足时停止相应读取与发现，不尝试绕过登录或访问限制。
- 数据不可信（过期、单位不一致、OCR 不清）记录数据质量问题，不伪装成经营差距。

本仓库公开。凭据、原始快照、会话与运行日志保留在授权本地位置；公开样例使用合成材料。审查模型请求、工具结果、日志的实际数据出口，不能从"本地计算"推导"零数据外传"；`.gitignore` 不替代内容审查。

发现投递遵循幂等与不丢不重：确认接收后再标记已送达；结果不明确时先核对回执，不盲目重放；取消、超时或恢复中不明的状态保留 UNKNOWN。代码回退不保证数据回退；数据兼容性和未知影响需另行核对。

## 8. 证据与进度

源码、长期测试、规格、正式决定和验收结论进入仓库的适用位置；原始命令输出、日志、候选清单和诊断现场保留在该任务明确的本地持久证据位置，初始本地检查可使用被忽略的 `.local/`。禁止把应保留的唯一证据放在临时目录。

记录候选和输入身份、实际命令与退出结果、适用环境/配置、复核范围及失败/未知。重要结论能追溯到验收与可访问证据；不只交摘要或哈希。进度说明验收推进、实际结果、缺口和下一步，普通里程碑不构成新的审批点。用户明确停止时停止相应任务，保留现场与返回点。不改写历史失败或把局部通过扩大为新产品验收。
